# 像素英语小镇：前端设计文档

## 1. 路由

| 路由            | 页面                | 访问控制                     |
| --------------- | ------------------- | ---------------------------- |
| `/`             | 像素小镇落地/认证页 | 公开；已登录时显示回访入口。 |
| `/town`         | 小镇总览            | 登录必需。                   |
| `/plaza`        | 学习广场            | 登录必需。                   |
| `/learn`        | 三栏学习页          | 登录必需。                   |
| `/me`           | 个人中心            | 登录必需。                   |
| `/admin/badges` | 徽章配置管理        | 管理员必需。                 |

## 2. 视觉与动效

- 像素风以小镇插画、建筑、地面纹理、像素边框和硬阴影表达；正文保持普通无衬线字体，保证长文可读性。
- 组件统一采用 2px 边框、`4px 4px 0` 硬阴影、小圆角（最大 4px）和有限色板。
- 首页点击后，场景整体向上移动，认证卡由下方进入；`prefers-reduced-motion` 下取消位移动效。
- 未开放建筑使用低饱和遮罩、锁定图标和悬浮文案“建设中”。

## 3. 页面说明

### 3.1 `/` 认证页

认证状态分为 `guest`、`auth-form`、`returning-user`。游客先看到场景；交互后进入认证卡。注册卡字段为昵称、邮箱、密码；登录卡仅为邮箱、密码。已登录用户显示“欢迎回到小镇，{nickname}”，主按钮为“进入小镇”。

### 3.2 `/town` 小镇总览

场景热点只能通过键盘和指针操作。中央学习广场（喷泉、公告栏或“前往学习”提示）跳转 `/plaza`；它周边以阅读小屋、词汇宝库、语法塔楼、拼写蜂巢、单词竞技场、对话咖啡馆、写作工坊、听力小屋、发音邮局、每日任务屋、知识花园、小镇大厅和码头构成能力地图。除学习广场外，所有热点显示锁定 Toast，且不会产生路由变化。页面提供个人中心和退出登录入口。

### 3.3 `/plaza` 学习广场

广场画面右上角仅常驻显示在线人数，不常驻展示榜单或动态列表。点击地图中的“学习榜”建筑后打开排行榜弹窗，用户可在“今日排行榜”和“连续学习榜”之间切换；点击“公告栏”后打开最近 50 条广场动态。移动端使用相同入口，弹窗适配窄屏并允许内部滚动。

进入页面后请求初始快照，再建立实时连接；所有在线用户同时收到“{用户名} 进入了学习广场”的进入动态与在线人数更新。进入、完成文章和获得徽章的实时动态使用同一套 Toast 视觉；历史动态只在用户主动打开公告栏时展示。新事件仅增量合并，重连后以快照为准。

### 3.4 `/learn` 学习页

| 区域     | 桌面端                               | 移动端              |
| -------- | ------------------------------------ | ------------------- |
| 文章列表 | 固定左栏，可切换文章                 | “文章”抽屉。        |
| 学习区   | 中间主栏，阅读、音频、逐词、完成     | 默认主体。          |
| AI 刷题  | 固定右栏，Key 状态、出题、答题、解析 | “AI 刷题”底部面板。 |

完成按钮需禁用重复提交；成功后刷新本地进度并显示新徽章提示。AI Key 输入框默认掩码，提供“本次会话保存”和“清除 Key”；不得将 Key 放入 URL、React DevTools 可见的持久状态、日志或埋点。

### 3.5 `/me` 个人中心

显示学习概览、学习热力/历史、徽章墙和 AI Key 状态。未获得徽章仅展示名称、条件和锁定样式；已获得徽章展示获得日期和当时的展示快照。

## 4. 前端状态与事件

```ts
type PlazaSnapshot = {
  presenceCount: number;
  leaderboards: { daily: LeaderboardEntry[]; streak: LeaderboardEntry[] };
  feed: PlazaFeedItem[];
  version: number;
};

type RealtimeEvent =
  | { type: 'presence.updated'; count: number; version: number }
  | { type: 'feed.created'; item: PlazaFeedItem; version: number }
  | { type: 'leaderboard.updated'; board: 'daily' | 'streak'; entries: LeaderboardEntry[]; version: number };
```

每个快照和增量事件均使用同一个单调递增的 `version`。前端仅应用 `version` 大于当前状态的增量事件；显式请求得到的快照始终作为该次连接的权威状态覆盖本地数据，以处理 Redis 重启或断线期间的版本重置。初始快照、断线重连、页面重新获得焦点时均可重新拉取快照。实时连接状态只影响提示，不阻塞学习和文章完成。
